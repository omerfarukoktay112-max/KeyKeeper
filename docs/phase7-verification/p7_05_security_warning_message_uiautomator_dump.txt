This also caught a real routing bug during this same manual pass: the first attempt declared
"security-warning" as AppShell's FIRST ShellContent, making it Shell's own implicit default page --
it was constructed (and SecurityWarningViewModel.Initialize() ran) before
IDeviceSecurityWarningService.EvaluateDeviceSecurity() had been called at all, so the message
rendered as an empty string; App.xaml.cs's later GoToAsync("//security-warning") turned out to be a
same-route no-op once Shell already considered itself there, so OnAppearing never re-fired to pick
up the real PendingWarning. Fixed by moving "security-warning" out of the first position in
AppShell.xaml (kept "setup" first, as it always was) -- see AppShell.xaml's own comment. The dump
above is from the corrected build.

Kilitli") afterward -- the underlying setup/lock/vault route AppRouting.DetermineInitialRoute would
have picked at launch.
